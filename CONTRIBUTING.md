# Contributing

1. Do not add private runtime files, credentials, model weights, or real chat logs.
2. Keep modules focused. A Bili receiver failure must not stop TTS, captions, memory, or music integration.
3. Add or update a Node test for behavioral changes.
4. Run `npm test` and `git diff --check` before opening a pull request.
5. Describe configuration changes in `docs/CONFIGURATION.md`.

Small, testable changes are easier to review and safer for a live environment `(•̀ᴗ•́)و`.
